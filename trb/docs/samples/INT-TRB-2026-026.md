# Review Intake Request: PrivateLink (front-end & back-end)

**Review ID:** TRB-2026-026 · **Feature:** `PrivateLink (front-end & back-end)@Security & Networking` · **Databricks phase at submission:** GA
**Requesting business unit:** Information Security · **Submitted:** 2026-04-03 · **Scheduled for:** TRBM-2026-04-21
**Primary reviewer:** CISO

## Business need
Information Security proposed PrivateLink (AWS PrivateLink) for front-end and back-end connectivity, keeping all Databricks traffic off the public internet. TRB reviewed endpoint configuration and traffic isolation.

## Intended use cases
- Private control-plane connectivity to Databricks
- Private data-plane traffic routing
- Off-public-internet data residency

## Risks identified by the requester
- Front-end PrivateLink alone allows data egress via internet
- Back-end PrivateLink adds cost and complexity
- NAT gateway still needed for non-Databricks egress

## Proposed mitigations
- Dual PrivateLink (front + back) required for PHI workloads
- Network policies restrict back-end routing
- NAT gateway egress filtered to approved destinations

## Reference
- Databricks documentation: https://docs.databricks.com/aws/en/security/network/
- Known limitations (tracker): Dual PrivateLink needed for full private path.
