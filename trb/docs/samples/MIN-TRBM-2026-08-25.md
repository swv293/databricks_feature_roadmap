### 2. TRB-2026-007: Mode: Databricks-to-Open (Sharing & Collaboration)

**Requestor:** [Platform Eng Lead]  
**Databricks Phase:** GA  
**Review Status:** Under Review

**Presentation Summary:** Mode enables Databricks-to-Open sharing: data owners grant external partners (non-Databricks customers) read-only access to shared tables via bearer token or OIDC. Use case: share member claims data with a third-party research organization under a Data Use Agreement (DUA) and BAA.

**Board Discussion:**
- **CISO:** "How long-lived is the bearer token?" → **Answer:** Token lifetime configurable (default 30 days); bearer token is single-use per query.
- **CPO:** "BAA with the research org—is that signed before sharing begins?" → **Answer:** Yes; Platform team confirms BAA in place before Mode share is provisioned.
- **Compliance Officer:** "Can we audit what external partner queried?" → **Answer:** Yes; Mode logs show recipient IP, query timestamp, rows returned. Logs retained in Databricks audit tables.
- **Enterprise Architect:** "What if recipient shares the token?" → **Answer:** Token is bearer-based; no way to prevent sharing. Mitigation: short lifetime (30 days), IP allowlist if possible, and anomaly detection on query patterns.

**Decision:** **✓ APPROVED WITH CONDITIONS**

| Condition ID | Requirement | Verification | Owner | Deadline |
|---|---|---|---|---|
| COND-007-1 | BAA signed with external recipient before Mode share provisioned | Legal department confirms BAA on file | Requestor | Per engagement schedule |
| COND-007-2 | Bearer token lifetime ≤30 days; IP allowlist enforced if recipient network known | Spot-check 3 active shares; verify token TTL and IP rules | TRB | 2026-10-25 |
| COND-007-3 | All Mode query audit logs retained 180 days; TRB conducts monthly anomaly check | Query audit review; escalate if >10x normal query volume | Platform Eng | 2026-10-25 |

### 3. TRB-2026-008: Databricks Apps – Follow-up

**Status:** **🔄 UNDER REVIEW (CONTINUED)**

**Rationale:** Code review process exists, but two critical questions remain: (1) **User vs. Service-Principal:** Can Databricks Apps run as a service principal (non-human)? If yes, how is service-principal credential rotation handled? (2) **Egress Testing:** How do we prevent an app from exfiltrating query results to an external endpoint? UC controls prevent unauthorized table access, but don't prevent app code from sending results outside. Need to test egress controls (firewall rules, VPC restrictions) with actual app deployment.

**Next Steps:** Platform Engineering to (a) confirm whether service-principal app execution is required for use case, and if so, design service-principal credential lifecycle; (b) conduct egress test in non-prod workspace. Re-present findings at TRBM-2026-09-22 or next meeting.
