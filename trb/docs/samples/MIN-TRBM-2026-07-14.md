### 1. TRB-2026-001: Row Filters & Column Masks (Platform & Governance)

**Requestor:** [Platform Engineering Lead]  
**Databricks Phase:** GA  
**Review Status (Before):** Not Reviewed

#### Presentation Summary
The Platform Engineering team presented row-level and column-level filtering capabilities within Databricks Unity Catalog (UC). Feature allows table owners to define masking policies (e.g., SSN display only last 4 digits) and row filters tied to user identity or roles. Already GA in Databricks; widely used by enterprise customers with HIPAA data. Platform team has no concerns.

#### Board Discussion
- **CPO:** "Is the mask policy persistent if a user runs `SELECT *`?" → **Answer:** Yes; mask applies regardless of query syntax. Immutable at the catalog layer.
- **Enterprise Architect:** "What's the performance impact?" → **Answer:** <2% overhead; masking applied at query compilation, not runtime.
- **Compliance Officer:** "Audit trail?" → **Answer:** All masking decisions logged to system tables; who queried what, when masking was applied, result set size.

#### Decision
**✓ APPROVED** – No conditions. Feature meets all HIPAA Technical Safeguard requirements (access control, audit logging). Row/column masking is a core control for member data protection.

**Review Decision Record:** DR-2026-001  
**PHI-Eligible:** ✅ Yes (GA + Approved)  
**Next Step:** Requestor may deploy immediately. Standard monitoring: quarterly query audit review by TRB.

### 2. TRB-2026-003: SQL Server (Cloud + On-Prem) Connector (Ingestion)

**Requestor:** [Data Governance Lead]  
**Databricks Phase:** Public Preview  
**Review Status (Before):** Not Reviewed

#### Presentation Summary
Databricks connector allows ingestion from SQL Server instances (cloud: Azure SQL DB, or on-prem: customer-hosted). Data Governance team wants to evaluate for ETL pipelines. Proposed use case: member demographics and claims metadata (non-PHI only, e.g., claim ID, date, amount—no diagnosis codes or member names). Azure SQL instances already use encryption; on-prem instances require TLS validation per team's network policy.

#### Board Discussion
- **CISO:** "On-prem SQL Server is high-risk if not hardened. What's your default assumption?" → **Answer:** We assume on-prem is NOT hardened unless customer certifies TLS 1.2+, encryption at rest, and password policy compliance.
- **Enterprise Architect:** "Where's the feature in Public Preview? Any known issues?" → **Answer:** Databricks documentation shows 2 reported issues (1 closed, 1 open minor bug). Databricks support SLA is <4hr for P1.
- **Compliance Officer:** "If PHI accidentally lands in the SQL Server connector, what's the audit trail?" → **Answer:** Databricks logs show source system, table names, row counts, user. If PHI detected, breach investigation can trace back to source.
- **CPO:** "You said non-PHI only. How do you enforce that?" → **Answer:** We'll implement role-based access to the connector and restrict it to approved non-PHI tables. But without technical row-level access control, we're relying on process (who can submit queries)."

#### Decision
**✓ APPROVED** – **Non-PHI Only (Condition).**

**Conditions:**
| Condition ID | Requirement | Verification | Owner | Deadline |
|---|---|---|---|---|
| COND-003-1 | SQL Server Connector access limited to approved non-PHI tables (claims metadata, counts, aggregates—no member names, SSN, diagnosis codes) | TRB audits monthly query audit logs | Data Governance | 2026-08-14 |
| COND-003-2 | For any on-prem SQL Server, customer must provide Databricks TLS certificate validation and encryption-at-rest audit | Review before connector is provisioned | Requestor | 2026-09-14 |

**Review Decision Record:** DR-2026-003  
**PHI-Eligible:** ❌ No (Public Preview phase, and non-PHI condition in place)  
**Monitoring:** Monthly query audit; escalate if PHI detected in results.  
**Upgrade Path:** When feature reaches GA, TRB will re-review for potential PHI use.

### 3. TRB-2026-004: Kafka-Compatible APIs (Ingestion)

**Requestor:** [Platform Engineering Lead]  
**Databricks Phase:** Beta  
**Review Status (Before):** Not Reviewed

#### Presentation Summary
Databricks Kafka API allows streaming ingestion of events into Delta tables. Platform team is investigating for real-time event processing (e.g., member claims events, system events). Kafka topics are currently internal only (no external integration planned). During intake, team noted desire for PHI streaming long-term.

#### Board Discussion
- **CISO:** "Feature is still Beta. What's Databricks' support SLA?" → **Answer:** Beta features are "best effort"—no contractual SLA. Databricks recommends not using Beta for production PHI workloads.
- **CPO:** "What does 'streaming' mean for audit? Can we replay / audit member data access?" → **Answer:** Kafka captures events; Databricks writes to Delta. Audit is possible but adds complexity—full replay may not be feasible.
- **Enterprise Architect:** "Is there row-level filtering on streaming data?" → **Answer:** Feature is not available yet; Databricks roadmap shows it for future release. For now, filtering would be post-ingestion.
- **Compliance Officer:** "In Beta, what's our breach liability if the feature has a bug?" → **Answer:** Any breach would be our liability (Databricks liability limited per support contract for Beta services).

#### Decision
**✗ REJECTED** – Out of compliance scope pending GA.

**Reason:** 
- Feature is in Beta, not GA. Per TRB charter, Beta features are out of compliance scope (no SLA for production use with PHI).
- Streaming audit trail is complex and not fully tested. Condition of PHI streaming cannot be verified reliably in Beta.
- Row-level filtering not available; cannot enforce necessary masking.

**Resubmit:** When Databricks reaches GA, requestor may resubmit with updated risk assessment addressing row-level filtering, audit replay capabilities, and SLA.

**Review Decision Record:** DR-2026-004  
**PHI-Eligible:** ❌ No (Rejected; Beta phase)  
**Next Step:** Platform team to re-evaluate for GA release. No production use recommended until re-reviewed.
