# Decision Record DR-2026-026: PrivateLink (front-end & back-end)

**Status:** Approved · **Approved scope:** PHI · **Decided at:** TRBM-2026-04-21
**Review:** TRB-2026-026 · **Feature:** `PrivateLink (front-end & back-end)@Security & Networking` · **Databricks phase at decision:** GA

## Context
Information Security proposed PrivateLink (AWS PrivateLink) for front-end and back-end connectivity, keeping all Databricks traffic off the public internet. TRB reviewed endpoint configuration and traffic isolation.

## Decision
PrivateLink is approved as a core requirement for the payer's PHI environment. Dual PrivateLink (front and back) is required for production PHI. Single PrivateLink is acceptable for non-PHI analytics.

## Risks considered
- Front-end PrivateLink alone allows data egress via internet
- Back-end PrivateLink adds cost and complexity
- NAT gateway still needed for non-Databricks egress

## Mitigations relied on
- Dual PrivateLink (front + back) required for PHI workloads
- Network policies restrict back-end routing
- NAT gateway egress filtered to approved destinations
