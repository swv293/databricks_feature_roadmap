## Feature Information

**Feature Name:** MCP (Model Context Protocol) Servers

**Feature Category:** Generative AI & Agents

**Databricks Release Phase:** GA

**Brief Description:** Model Context Protocol (MCP) enables Databricks agents to call external APIs and tools via standardized interfaces. MCP servers are integrations with external systems (e.g., web APIs, internal databases). Acme Health Plan is evaluating MCP to connect agents to clinical decision support tools and member eligibility systems.

## Use Case and Business Justification

**What problem does this feature solve for Acme Health Plan?**

Clinicians and care managers need to answer questions like "Is this medication covered under the patient's plan?" or "What are the FDA-known interactions with this drug?" Currently, this requires manual lookup in multiple systems. Databricks agents with MCP servers could automate these lookups, improving clinical decision-making speed and accuracy.

## Known Risks & Questions

**What concerns do you anticipate?**

1. **External API Security:** FDA Drug Interaction API is public (no auth required). Is it HIPAA-compliant? Databricks is sending drug names (not PHI), but are we exposing query patterns or member demographics indirectly?

2. **Internal API Authentication:** Member Eligibility System uses API key. If key is compromised, attacker could query all member coverage. Need to assess key rotation policy and scope (can the key query all members, or is it scoped?).

3. **MCP Server Audit Trail:** If agent calls an MCP server, is the request and response logged? By Databricks? By the external system? Needed for breach investigation.

4. **Error Handling:** If an MCP server returns an error, could it leak information (e.g., "Member ID 123 not found" vs. "Authentication failed")? Timing attacks?

5. **Data Retention:** External APIs may cache or log requests. Does FDA API store queries? Does Acme's internal eligibility system log who queried what member? TRB needs confirmation.

**Which security controls are most critical?**
- API authentication/authorization (API key security, scope)
- Data transmission encryption (TLS 1.2+)
- Audit logging (request, response, user, timestamp)
- Rate limiting (prevent abuse/scanning)
- Error messages (no data leakage)
- BAA confirmation (if external APIs handle PHI)
