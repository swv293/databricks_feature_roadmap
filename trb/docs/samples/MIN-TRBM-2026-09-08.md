## Agenda

### 1. Exception Request Review

#### EXC-2026-001: SQL Server Connector with PHI (Early GA Waiver)

**Requestor:** [Data Governance Lead]  
**Request:** Use SQL Server Connector (currently approved non-PHI only per TRB-2026-003) with **limited PHI scope** before feature reaches GA (if ever).

**Business Case:** Quarterly Financial Reconciliation process compares member claims in Databricks with claims in legacy SQL Server system. Currently manual; requires matching member ID, DOS, and claim amount across systems. Non-PHI column matching is insufficient; need to include member name for manual validation. Request: allow phased pilot using member name + ID (non-sensitive PHI) only.

**Proposed Mitigations:**
- Pilot scope: 1000 sample member records (non-random sample, selected by Finance team)
- Duration: 90 days (Sept 8 – Dec 8, 2026)
- Users: 2 Finance analysts (must complete HIPAA training)
- Data: Member name + ID only (no SSN, DOB, diagnosis)
- Access: Query log audit monthly; Finance manager spot-checks 5 queries

**Board Discussion:**
- **CISO:** "Is member name + ID considered PHI?" → **Answer:** Under HIPAA, member name + medical record number is PHI. But in this case, the combination is used for data matching, not clinical purposes. Risk is low if isolated to 1000 records.
- **Enterprise Architect:** "Why can't you use a hash of member ID for matching?" → **Answer:** Hashing removes the ability to do QA validation; Finance needs to spot-check actual names for accuracy.
- **Compliance Officer:** "What if someone uploads the matched file to an unencrypted drive?" → **Answer:** Risk. Finance team will sign data handling agreement; TRB will spot-check no exports.
- **Data Governance Lead:** "This is 90 days. What's the long-term solution?" → **Answer:** SQL Server connector should reach GA next quarter (est. Oct 2026); at that time, TRB re-review for standard PHI use.

**Board Vote:**
- CISO: ✗ Deny
- CPO: Excused (consulted via async; concurs with denial rationale)
- Enterprise Architect: ✗ Deny
- Platform Eng Lead: ✗ Deny
- Data Governance Lead: ✗ Deny (abstained from vote due to conflict)
- Compliance Officer: ✗ Deny
- Other: ✗ Deny

**Decision:** **✗ DENIED** (Unanimous; 6 voted, 1 abstained, 1 excused)

**Denial Rationale:** 
SQL Server Connector is in Public Preview. Per TRB charter and HIPAA compliance scope, **Public Preview features are subject to compliance restrictions and cannot carry PHI.** Member name + ID is PHI under 45 CFR § 164.102 (individually identifiable health information). The connector's Public Preview status means it lacks the SLA and maturity guarantees required for production PHI handling. Finance cannot use this feature for PHI until: (1) Databricks advances the connector to GA, AND (2) TRB re-reviews it for PHI use.

**Alternatives Offered:**
1. Use an already-approved GA ingestion path (e.g., Auto Loader file ingestion, TRB-2026-013, approved for PHI), with row filters and column masks on the landed Delta tables, to perform the reconciliation.
2. Wait for SQL Server Connector to reach GA, then resubmit both a TRB review request AND an exception request if still needed.

**Exception ID:** EXC-2026-001  
**Status:** Denied
