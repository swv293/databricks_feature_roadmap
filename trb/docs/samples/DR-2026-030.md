# Decision Record DR-2026-030: Enhanced Security Monitoring

**Status:** Approved · **Approved scope:** PHI · **Decided at:** TRBM-2026-05-19
**Review:** TRB-2026-030 · **Feature:** `Enhanced Security Monitoring@Security & Networking` · **Databricks phase at decision:** GA

## Context
Information Security selected Enhanced Security Monitoring (ESM) to add malware, file-integrity, and vulnerability monitoring on compute handling PHI. TRB reviewed agent overhead and alert handling.

## Decision
Enhanced Security Monitoring is approved for production PHI workloads on classic compute. ESM is required for all production clusters running PHI. ESM coverage for serverless compute is to be confirmed with the account team.

## Risks considered
- Monitoring agent impacts cluster performance
- False positives overwhelm security team
- Classic-compute-only limitation

## Mitigations relied on
- Agent overhead <5% CPU; tuned sampling rates
- Alert thresholds and allowlists reduce false positives
- Serverless compute ESM roadmap exists but not yet approved

## Control mappings
- HIPAA-Security-Rule 164.308(a)(5)(ii)(A) (Log-in monitoring): Satisfied
- NIST-800-53-R5 SI-4 (System Monitoring): Satisfied
- HITRUST-CSF 10.c (Log Reviews, Monitoring and Alerting): Satisfied
