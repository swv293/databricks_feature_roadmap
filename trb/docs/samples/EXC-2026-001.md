## 1. What is Being Requested?

**Feature Name:**  
SQL Server Connector (Cloud + On-Prem)

**Current TRB Status:**  
Approved – Non-PHI only (TRB-2026-003, approved July 14, 2026)

**Exception Request:**  
We request a **phased waiver** to use SQL Server Connector with **limited PHI scope** (member name + ID only, non-sensitive PHI) for the **annual member reconciliation project** before the feature reaches GA.

**Specific Override:**  
Normally, SQL Server Connector is approved for non-PHI data only (claims counts, amounts, dates—no member identifiers). We are asking TRB to allow **member name + ID** (linked reconciliation) for the reconciliation process. This is non-sensitive PHI under HIPAA (name + member ID, without diagnosis/medical data), but expands beyond the current non-PHI-only scope.

## 2. Business Justification

**Why is this request important to Acme Health Plan?**

Our annual Financial Reconciliation process compares member claims in Databricks against the legacy SQL Server claims system. This ensures accuracy, detects data entry errors, and supports financial audit compliance.

**Current Process (Manual):**
- Finance team exports claim data from both systems
- Manually matches claims using member ID + DOS + claim amount (no member names, to avoid PHI exposure)
- Manual matching is error-prone; ~2% of claims require manual investigation
- Process takes 6 weeks; requires 2 FTE Finance analysts
- High risk of human error; audit findings cite reconciliation delays

**Proposed Process (Automated via SQL Server Connector):**
- Query both Databricks and SQL Server using member name + ID as matching key
- Automated join; validates amounts match
- Identifies discrepancies in <1 day
- Reduces FTE from 2 to 0.5
- Higher accuracy; audit-friendly

**Business Impact:**
- Cost savings: ~$100K/year (1.5 FTE reduction)
- Accuracy improvement: Reduce reconciliation errors from 2% to <0.1%
- Timeline: Complete by December 31, 2026 (fiscal year-end audit deadline)
- Strategic: Enables annual audit sign-off on schedule

**Key Success Metrics:**
- Reconciliation completed by Dec 31, 2026 ✓
- Zero PHI breaches during pilot ✓
- Audit findings: "Reconciliation controls improved" ✓

**Example Query:**  
```sql
SELECT 
  datalake.members.member_id,
  datalake.members.member_name,
  COUNT(datalake.claims.claim_id) as claim_count,
  SUM(datalake.claims.claim_amount) as total_amount
FROM legacy_sql_server.claims cs
INNER JOIN datalake.members ON cs.member_id = datalake.members.member_id
WHERE datalake.members.member_id IN (SELECT member_id FROM [list of 1000 reconciliation members])
GROUP BY datalake.members.member_id, datalake.members.member_name
```

**Result: DENIED** (6 members voted; 6 in favor of denial, 0 opposed, 1 abstained, 1 excused)

**Denial Rationale:**

Per TRB charter and HIPAA compliance framework, **Public Preview features are subject to compliance restrictions and cannot carry PHI.** Member name + member ID is PHI under 45 CFR § 164.102. The SQL Server Connector's Public Preview status means:
- No contractual SLA; support is "best effort"
- No maturity guarantees; feature may change or be deprecated
- Insufficient testing/hardening for production PHI handling

**Alternatives Offered:**

1. **Use approved GA path:** Row Filters & Column Masks (TRB-2026-001, already approved for PHI) can enforce member data filtering on a Databricks SQL table. Perform reconciliation using already-approved masking + filtering capabilities.

2. **Wait for GA:** When Databricks advances SQL Server Connector to GA, resubmit both a TRB feature review (for standard PHI scope) AND a new exception request (if still needed). At that time, with GA SLA and maturity, TRB will reassess.

Finance Department's business case is noted and appreciated. The denial is based on feature maturity, not business priority.
