## Agenda & Decisions

### 1. TRB-2026-002: Attribute-Based Access Control (ABAC) (Platform & Governance)

**Requestor:** [Enterprise Architect]  
**Databricks Phase:** GA  
**Review Status (Before):** Not Reviewed

#### Presentation Summary
ABAC extends UC permissions by allowing fine-grained access based on attributes (e.g., user department, data region, sensitivity level). Feature is GA; widely adopted by enterprise customers. Acme Health Plan plans to tie member data access to user's region (North, South, East, West regions only see their regional member data).

#### Board Discussion
- **CPO:** "How is the attribute assigned to the user? Is it in a directory (Active Directory, Okta)?" → **Answer:** Yes, attributes stored in Okta; Databricks pulls at session start. Cached for 1 hour.
- **CISO:** "Audit trail—can we see which attributes were evaluated?" → **Answer:** Yes; system tables log attribute lookups and decisions.
- **Enterprise Architect:** "If Okta is compromised, can an attacker escalate?" → **Answer:** Attacker would need to modify Okta attributes; requires separate Okta admin credentials and audit trail. Mitigation: MFA on Okta admins + quarterly Okta access review.

#### Decision
**🔄 UNDER REVIEW** – Requested deferred to next meeting pending **deep dive on Okta integration**.

**Rationale:** While ABAC itself is GA and sound, Acme Health Plan's use case depends on Okta attribute integrity. TRB wants to schedule a security review of Okta configuration (MFA enforcement, admin access logging, backup/restore controls) before ABAC is approved for PHI use.

**Next Steps:**
- Enterprise Architect to coordinate Okta review with Identity & Access Management team.
- Re-present at TRBM-2026-08-25 with Okta security assessment.

### 2. TRB-2026-005: Genie One (SQL & BI Analytics)

**Requestor:** [Analytics Manager]  
**Databricks Phase:** GA  
**Review Status (Before):** Not Reviewed

#### Presentation Summary
Genie One is Databricks' natural-language query generator. Users ask questions in English (e.g., "Show me member claims by region"); Genie generates SQL and returns results. GA feature. Analytics team proposes use for member analytics queries (e.g., "How many claims did members aged 65+ file in Q2?"). Potential to enable non-technical stakeholders to explore member data.

#### Board Discussion
- **CPO:** "Does Genie store the natural-language prompt or any query history on Databricks servers?" → **Answer:** TBD pending Databricks account-team confirmation. Assume prompts/results remain in customer workspace. To be verified in COND-005-1 audit logs before condition sign-off.
- **Compliance Officer:** "What if a user accidentally asks a question that reveals PHI (e.g., 'Show me all claims for Social Security number 123-45-6789')?" → **Answer:** Good catch. Genie generates SQL, but the user's question itself is sensitive. TRB should require all Genie queries be logged and monitored for PHI patterns.
- **Enterprise Architect:** "Row-level access control—does Genie respect UC row filters?" → **Answer:** Yes; Genie-generated SQL is subject to the same row/column masking as manual queries. If user doesn't have permission to a column, Genie won't query it.
- **Data Governance Lead:** "What about query responses—could Genie's result summary leak PHI?" → **Answer:** Genie shows aggregates and visualizations, not raw data. But if user asks "Show me all members with diabetes," and result is "1 member," that's a privacy issue (quasi-identifier). TRB needs to address this.

#### Decision
**✓ APPROVED WITH CONDITIONS** – See conditions below.

**Rationale:** Genie One is GA and useful for analytics. Risk is mitigatable with strong logging and response monitoring.

| Condition ID | Requirement | Verification | Owner | Deadline |
|---|---|---|---|---|
| COND-005-1 | All Genie queries (natural-language prompt + generated SQL + result count) logged to system tables; retained 180 days | TRB audits sample logs monthly | Analytics | 2026-09-15 |
| COND-005-2 | Row-level access control (UC row filters) enforced; test queries to verify masking | Spot-check 5 test queries with test users | Analytics | 2026-09-15 |
| COND-005-3 | Genie result sets limited to aggregates/visualizations; no raw PHI in responses (verify via query results sampling) | Monthly audit of 10 Genie queries' result sets | Databricks Support + Analytics | 2026-09-15 |
| COND-005-4 | User training on responsible Genie use (e.g., don't ask "Show me all members with X diagnosis"); training required before access | Training completion certificates | Analytics Manager | 2026-09-15 |

**Review Decision Record:** DR-2026-005  
**PHI-Eligible:** ✅ Yes (GA + Conditions will be met)  
**Conditional Approval Letter:** To be issued 2026-07-29
